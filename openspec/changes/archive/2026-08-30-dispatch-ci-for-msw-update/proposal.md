## Why

Pull requests generated by the MSW update workflow do not run the normal
frontend CI because pushes made with `GITHUB_TOKEN` do not trigger another
workflow. The update workflow must explicitly dispatch CI for its generated
branch so the automated dependency update receives the same validation as
other changes.

## What Changes

- Allow the frontend CI workflow to be started manually without inputs while
  preserving its existing push trigger.
- After an MSW update is pushed and its pull request is created or reused,
  dispatch frontend CI against `chore/update-msw` using `GITHUB_TOKEN`.
- Skip CI dispatch when the MSW update produces no changes.
- Grant the MSW update workflow only the additional permission required to
  dispatch CI.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `manual-msw-update`: Require changed MSW update branches to run the normal
  frontend CI through an explicit workflow dispatch while preserving no-op and
  pull request reuse behavior.

## Impact

- `.github/workflows/ci.yml` gains a no-input `workflow_dispatch` trigger.
- `.github/workflows/update-msw.yml` gains minimal Actions permission and a
  post-push/PR CI dispatch step using the existing workflow token.
- No PAT, GitHub App token, dependency, application API, or runtime behavior is
  introduced.
